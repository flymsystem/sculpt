# D Sculpt Fitness — Landing Rebuild + SaaS Visual Refinement

Date: 2026-08-17
Status: approved, in implementation

## Goal

Raise the product's visual and usability quality without changing what it
does. The landing page is rebuilt against a decoded Figma reference; the
SaaS is refined in place. No functional, data, auth or routing changes
beyond one additive database migration.

## Non-goals

- No React migration. The app is vanilla ES modules + Vite; it stays that way.
- No new navigation items, pages or features.
- No changes to Supabase queries, RLS (beyond the additive policy below),
  auth, permissions, WhatsApp, GST, invoice or backup logic.
- No fabricated data: no invented prices, addresses, trainers or metrics.

## Reference

`reference/*.fig` is a Figma community gym template. It is a ZIP containing
`canvas.fig` (Kiwi-encoded), `thumbnail.png` and 26 image assets. Decoded
with `scripts/figdec` (scratchpad) — 631 schema definitions, 884,380 bytes
of node data consumed cleanly.

Frames: `gym24 - 1600` (1600x5142), `1000` (1000x5461), `744` (744x5259),
`393` (393x4069), plus a `UI Kit` frame.

### Brand overrides applied to the reference

- The reference accent `#faff00` (yellow) maps to D Sculpt blue `#0A84FF`
  everywhere. No yellow ships.
- The reference's display face (MADE Outer Sans / Bruno Ace SC) is replaced
  by the existing Manrope + Barlow Condensed pairing already in the repo.
- The reference's Trainers section is dropped entirely, per instruction.
  Its 8 trainer portrait assets are not shipped.

## Photography

Only `e3697832` (dark gym, athlete with weight plate) is brand-neutral and
ships in full colour as the hero. Every interior shot in the reference is
from a yellow-branded gym (yellow rigs, yellow wall type, a competitor
wordmark on the wall).

**Duotone treatment.** Interiors are rendered black-and-blue in CSS:
`grayscale(1)` strips the yellow completely, then a D Sculpt blue layer is
composited over the midtones and a dark scrim is laid on top. The palette
is exactly the existing brand set — blue `#0A84FF`, chrome `#C8CDD6`, ink
`#050507` — so photography, logo and UI share one colour story. The hero
is deliberately exempt: it is already dark and neutral, and grading it
would flatten the one genuinely good photograph.

Assets are generated by `scripts/prep-landing-images.mjs` (Playwright's
Chromium as the resizer — no native image dependency) into `public/img/`.
Total 5.9MB of source reduced to 506KB.

## Logo

The asset is a circular badge: "SCULPT FITNESS" arced around a chrome ring
with a figure mark at centre. There is no separate wordmark and no
mark-only variant, so "full logo vs mark" is one asset at two size
registers. The badge already contains the brand name, so the duplicated
HTML text lockup beside it is removed wherever the badge is large enough
to read.

| Surface | Before | After |
|---|---|---|
| Landing navbar | 34px + text | 48px, text dropped |
| Landing footer | 30px | 56px |
| Login | 72px | 120px |
| Sidebar | 40px | 56px |

There is no collapsed-sidebar variant to size: `--sidebar-collapsed-w` is
declared in `tokens.css` but no code ever applies it, so the sidebar has
only one state. A mark-only treatment was not invented for a state that
does not exist.

`public/icon-*.png` were the wrong source: they render the badge on an
opaque `#050507` plate for the PWA/favicon, which showed as a black square
behind the mark on every in-app surface. `scripts/prep-logo.mjs` builds
`public/logo-{128,256,512}.png` from `sculp-logo.png` instead — the bare
circular mark on transparency, trimmed to its own bounding box so no dead
padding eats into the rendered size. The UI uses those; the icon-*.png
assets keep their plate and stay reserved for the manifest and favicon.

Never scaled non-uniformly, never cropped, never placed on a light ground
without the badge's own dark disc behind it.

## Landing structure

Nav → Hero → Why People Stay → What We Train → Membership → About →
Final CTA → Footer.

**Hero.** Full-bleed photograph bleeding to the right edge, dissolved into
black on both sides by linear-gradient scrims — the reference's own
technique, and the fix for the current empty black area. Headline sits
low-left at the 64px step, then a short supporting line, then the CTA row.

**Membership.** Reads live from Plan Settings (see migration). Shows plan
name, duration, price and a Contact CTA. If the migration has not been
run, or the gym has no active plans, the section hides itself rather than
erroring or showing invented prices.

**Copy.** Primary CTA is "Contact us", not a free-trial offer.

**Content.** Address is Malagala, Bangalore. Phone, WhatsApp, email and
hours are not yet supplied; they render as muted "to be supplied" chips so
they read as an obvious to-do rather than shipped copy, and all live in
one `GYM` config object at the top of `landing.js`.

## Database migration (additive, must be run by the owner)

Landing membership requires anonymous read of active plans. `plans` today
has no anon policy. The migration adds a read-only policy exposing only
`name`, `price`, `duration` for active plans. It grants nothing else, and
touches no other table, no member data and no financial data.

Until it is run the landing membership section is simply absent. Nothing
else on the page or in the SaaS depends on it.

## SaaS refinement

Typography needs less work than assumed: Manrope is already
`--font-sans` and already loads via `global.css`. The dashboard already
avoids the condensed display face. Work concentrates on:

- **Consistency** — one radius scale, one spacing scale, one badge and
  table treatment across pages, replacing per-page drift.
- **Logo sizes** — as tabled above.
- **Empty states** — Finance, Plans, Analytics and Members get honest
  empty states instead of blank panels or zero-value charts.
- **Loading** — skeletons rather than empty dark cards.
- **Analytics** — rebuilt around four questions: what happened, how are we
  doing, what needs attention, what should I do. KPI row, two primary
  charts (member growth, revenue trend), member health, plan performance,
  payment health, and insights computed from real data only. Any metric
  that cannot be derived from existing queries is not shown.
